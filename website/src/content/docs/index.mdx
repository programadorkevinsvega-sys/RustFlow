RustFlow es un framework web en Rust en etapa de prototipo. Su repositorio incluye un runtime reactivo, componentes y vistas tipadas, un renderer DOM para WebAssembly, serialización SSR, composición de páginas y un servidor HTTP experimental. Las APIs son pre-1.0 y todavía no se recomienda RustFlow para producción.

**Esta documentación explica las APIs que existen en el código**, no una promesa de lo que el framework espera implementar. Cada guía identifica su caso de uso, muestra código o enlaza con un ejemplo ejecutable, explica las decisiones, menciona los errores habituales y declara las limitaciones.

## Qué puedes construir hoy

- Sitios de contenido y prototipos SSR con vistas estructurales, documentos HTML y páginas de error.
- Interfaces WASM interactivas con señales, efectos, memos derivados, contextos tipados, refs Rust y DOM, eventos, listas keyed, fragments y formularios controlados.
- Servicios HTTP con rutas, parámetros, query/JSON, middleware, grupos, respuestas y límites configurables.
- Endpoints que extraen y validan formularios, JSON y query tipados, devuelven errores 422 estructurados y pueden proteger mutaciones mediante CSRF optativo.
- Páginas compuestas con un catálogo de componentes compartido, datos de ruta explícitos y layouts anidados.
- Aplicaciones con persistencia relacional experimental mediante SeaORM sobre pools SQLx tipados y loaders explícitos.
- Aplicaciones documentales con el ODM MongoDB independiente, filtros/updates BSON, proyecciones, agregaciones y operaciones explícitas con sesiones de MongoDB.
- Navegación de cliente optativa y mejora progresiva de formularios GET compatibles, conservando el comportamiento nativo cuando la interacción no es compatible.

El [catálogo de ejemplos](/reference/examples/) conecta cada caso con un archivo y un comando. La [guía de pruebas](/guides/testing/) explica cómo verificar el comportamiento localmente.

## Lo que no debes asumir

El CLI experimental genera aplicaciones de servidor nativo y delega compilación a Cargo; `rustflow new --template crud` añade un proyecto didáctico con ORM SQL, validación, transacciones, auth, CSRF y SSR. No incluye hot reload ni un bundler integrado para browser/WASM. El generador `rustflow generate model` sigue produciendo un struct de dominio plano por compatibilidad: no crea automáticamente entidades SeaORM ni implementaciones `DocumentModel`. La configuración de la Fase 6.2 cubre perfil, host y puerto. `use_memo`, `use_ref` y `use_context` están disponibles de forma experimental en Phase 7.2; las referencias a nodos DOM usan el handle separado `rustflow_dom::ElementRef` y solo están disponibles en browser/WASM. No hay Resources/Suspense ni ErrorBoundary de componentes. Las APIs de sesión y guards de la Fase 6.4 son experimentales; `InMemorySessionStore` es volátil y local al proceso, no hay proveedor de usuarios y todavía no existe un `SessionStore` SQL durable.

La Fase 6.6 está completa, con la matriz verificada publicada: SQLite 3.46.0, PostgreSQL 16.15, MySQL 8.4.13 LTS, MariaDB 11.4.13 LTS y MongoDB 7.0.45. La Fase 6.7 (ORM SQL y ODM documental) quedó completada en `main` mediante PR #66, squash merge `6046ae7ca60843d145476177e698162b57939c68`. Incluye SeaORM 1.1.20 sobre un único pool SQLx tipado compartido, `EntityRepository` para CRUD/bulk y consultas tipadas, loaders y grafos relacionales explícitos, transacciones, ODM MongoDB separado y una aplicación CRUD educativa con relación Category/Product, filtros y paginación. El gate de calidad/compatibilidad verificó pool exhaustion y recuperación, escrituras concurrentes, seguridad de valores SQL/BSON, migraciones PostgreSQL repetibles/reversibles y benchmark smoke ORM/ODM. El HEAD final `b049d96491e2b23bfe794ac3c0ed9abb68f7e493` pasó los checks requeridos en Rust 1.85/stable, WASM, Browser E2E/bundle, documentación, governance, dependency review y Cloudflare Pages. El ORM y el ODM continúan siendo APIs experimentales/pre-1.0; el CRUD generado no es un starter de producción. Consulta la [matriz de versiones](/guides/database/#matriz-de-versiones-verificadas), la [guía de base de datos](/guides/database/), la [guía ODM](/guides/mongodb-odm/) y [Estado del proyecto](/project-status/).

La Fase 6.7 está completada: 6.7.1–6.7.6 están implementadas, verificadas e integradas en `main`. La aplicación `--template crud` quedó aceptada como demostración de integración, no como plantilla de producción. Siguen fuera de esta fase y pendientes server actions, proveedor de usuarios, sesiones durables y una receta de despliegue de producción validada. El callback de navegación cliente no es un router general y la mejora progresiva de formularios se limita a GET URL-encoded compatibles; no procesa uploads ni mutaciones. Consulta la [guía de formularios](/guides/forms-validation/), la [guía de sesiones](/guides/sessions-and-access/), [Estado del proyecto](/project-status/) y [referencia de disponibilidad de API](/reference/api-status/).

## Si ya conoces React

Los nombres `use_state` y `use_effect` son helpers de RustFlow ligados al scope propietario, pero el modelo es signal-first: no usa celdas de estado por orden de hooks y no promete compatibilidad con React. Aprende el contrato real en [Reactividad](/concepts/reactivity/) y [Componentes](/guides/components/).
