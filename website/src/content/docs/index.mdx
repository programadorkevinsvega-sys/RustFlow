RustFlow es un framework web en Rust en etapa de prototipo. Su repositorio incluye un runtime reactivo, componentes y vistas tipadas, un renderer DOM para WebAssembly, serialización SSR, composición de páginas y un servidor HTTP experimental. Las APIs son pre-1.0 y todavía no se recomienda RustFlow para producción.

**Esta documentación explica las APIs que existen en el código**, no una promesa de lo que el framework espera implementar. Cada guía identifica su caso de uso, muestra código o enlaza con un ejemplo ejecutable, explica las decisiones, menciona los errores habituales y declara las limitaciones.

## Qué puedes construir hoy

- Sitios de contenido y prototipos SSR con vistas estructurales, documentos HTML y páginas de error.
- Interfaces WASM interactivas con señales, efectos, componentes, eventos, listas keyed y limpieza.
- Servicios HTTP con rutas, parámetros, query/JSON, middleware, grupos, respuestas y límites configurables.
- Endpoints que extraen y validan formularios, JSON y query tipados, devuelven errores 422 estructurados y pueden proteger mutaciones mediante CSRF optativo.
- Páginas compuestas con un catálogo de componentes compartido, datos de ruta explícitos y layouts anidados.
- Navegación de cliente optativa y mejora progresiva de formularios GET compatibles, conservando el comportamiento nativo cuando la interacción no es compatible.

El [catálogo de ejemplos](/reference/examples/) conecta cada caso con un archivo y un comando. La [guía de pruebas](/guides/testing/) explica cómo verificar el comportamiento localmente.

## Lo que no debes asumir

El CLI es experimental y genera un servidor nativo; no ofrece hot reload ni un bundle browser automático. La configuración de la Fase 6.2 valida únicamente perfil, host y puerto, y producción requiere variables del proceso. `use_memo`, `use_ref` y `use_context` siguen pendientes. Las primitivas experimentales de sesión, identidad y guards de la Fase 6.4 ya están integradas en `main`, pero el adaptador en memoria no ofrece persistencia durable ni coordinación entre procesos y no hay proveedor de usuarios. La integración SQLx de la Fase 6.5 proporciona pool, transacciones, migraciones versionadas y mapeo de errores para SQLite/PostgreSQL. PR #54 está fusionada en `main` como `48a491d660c71005b58ed88a4f6a7e8ba3390c9d` e incorpora el driver SQLx `mysql` compartido por MySQL y MariaDB; sus contratos históricos de MySQL 8.0/MariaDB 11.4 pasaron con Rust 1.85/stable; la Phase 6.6.3 propone para la matriz actual MySQL 8.4.13 LTS y MariaDB 11.4.13 LTS. PR #55 añadió el adaptador documental MongoDB independiente de SQLx y está fusionada en `main` como `e3ceb86d757bb7aa1a07e16a1e21b462adb69841`; el HEAD final `8c1a33c261769bd731f00c371bac17a569611c68` pasó CI en Rust estable y Rust 1.85, incluida la integración real de MongoDB 7.0.45, junto con WebAssembly, Browser E2E/bundle, documentación, gobernanza y revisión de dependencias. El adaptador MongoDB sigue siendo experimental, acepta `mongodb://` y rechaza `mongodb+srv://` por la restricción de seguridad del resolver DNS. La Fase 6.6 continúa en progreso mientras la subfase 6.6.3 valida el contrato de versiones SQLite 3.46.0 bundled, PostgreSQL 16.15, MySQL 8.4.13 LTS, MariaDB 11.4.13 LTS y MongoDB 7.0.45, incluyendo runtime assertions, MSRV y los ejemplos de configuración. Consulta la [matriz pública](/guides/database/#matriz-de-versiones-verificadas); la fase no se cierra hasta que todos los checks del HEAD final pasen. La Fase 6.7 planifica un ORM SQL para SQLite/PostgreSQL/MySQL/MariaDB y una API documental/ODM independiente para MongoDB; esas APIs de mapeo siguen siendo futuras y no están implementadas. La Fase 6.7 exige un ORM SQL y un mapeador documental diseñados para alcanzar madurez desde el inicio; sus subfases no permiten cerrar el hito con un ORM mínimo de solo CRUD. Una prueba del CLI genera y ejecuta una aplicación CRUD para verificar validación, persistencia, sesión/autenticación, CSRF y páginas renderizadas; el scaffold por defecto sigue siendo genérico y no crea ese flujo de negocio automáticamente. La integración es experimental: no hay ORM, sesiones SQL durables ni proveedor de usuarios. Server actions y una receta de despliegue de producción siguen pendientes. La Fase 6.3 aporta validación tipada, middleware CSRF optativo y redirección segura de retorno; consulta la [guía de formularios](/guides/forms-validation/) y la [guía de sesiones](/guides/sessions-and-access/). El callback de navegación cliente no es un router general y la mejora de formularios no procesa cargas de archivos ni mutaciones. Consulta [Estado del proyecto](/project-status/) y [referencia de disponibilidad de API](/reference/api-status/).

## Si ya conoces React

Los nombres `use_state` y `use_effect` son helpers de RustFlow ligados al scope propietario, pero el modelo es signal-first: no usa celdas de estado por orden de hooks y no promete compatibilidad con React. Aprende el contrato real en [Reactividad](/concepts/reactivity/) y [Componentes](/guides/components/).
