RustFlow es un framework web en Rust en etapa de prototipo. Su repositorio incluye un runtime reactivo, componentes y vistas tipadas, un renderer DOM para WebAssembly, serialización SSR, composición de páginas y un servidor HTTP experimental. Las APIs son pre-1.0 y todavía no se recomienda RustFlow para producción.

**Esta documentación explica las APIs que existen en el código**, no una promesa de lo que el framework espera implementar. Cada guía identifica su caso de uso, muestra código, explica las decisiones, menciona los errores habituales y declara las limitaciones.

## Una ruta de aprendizaje

- [1. Empezar desde cero](/getting-started/setup/): clonar el repositorio, ejecutar tests y conocer los workflows actuales.
- [2. Aprender estado y efectos](/concepts/reactivity/): señales, dependencias, batching, scopes y limpieza.
- [3. Crear componentes](/guides/components/): vistas, props, eventos, estado y listas keyed.
- [4. Crear rutas HTTP](/guides/server/): HTML, JSON, parámetros y middleware.
- [5. Renderizar HTML en servidor](/guides/ssr/): escape, documentos completos, catálogo e hidratación optativa.
- [6. Compartir estructura con layouts](/guides/layouts/): composición de páginas y datos públicos.
- [7. Añadir navegación progresiva](/guides/navigation/): historial, enlaces elegibles y formularios GET.
- [8. Crear una página de producto](/tutorials/product-page/): conectar rutas, props, catálogo SSR y layouts.

## Qué puedes construir hoy

- Sitios de contenido y prototipos SSR con vistas estructurales, documentos HTML y páginas de error.
- Interfaces WASM interactivas con señales, efectos, componentes, eventos, listas keyed y limpieza.
- Servicios HTTP con rutas, parámetros, query/JSON, middleware, grupos, respuestas y límites configurables.
- Páginas compuestas con un catálogo de componentes compartido, datos de ruta explícitos y layouts anidados.
- Navegación de cliente optativa y mejora progresiva de formularios GET compatibles, conservando el comportamiento nativo cuando la interacción no es compatible.

## Lo que no debes asumir

Todavía no hay un CLI propio, scaffolding, <code>use_memo</code>, <code>use_ref</code>, <code>use_context</code>, sesiones/autenticación integradas, CSRF, server actions, persistencia integrada ni una receta de despliegue de producción. El callback de navegación cliente no es un router general y la mejora de formularios no procesa cargas de archivos ni mutaciones. Consulta [Estado del proyecto](/project-status/) y [referencia de disponibilidad de API](/reference/api-status/).

## Si ya conoces React

Los nombres <code>use_state</code> y <code>use_effect</code> son helpers de RustFlow ligados al scope propietario, pero el modelo es signal-first: no usa celdas de estado por orden de hooks y no promete compatibilidad con React. Aprende el contrato real en [Reactividad](/concepts/reactivity/) y [Componentes](/guides/components/).
